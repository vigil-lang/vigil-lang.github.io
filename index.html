Por que Vigil?Why Vigil?

eBPF é poderoso, mas escrever eBPF em C significa brigar com o verificador. Vigil leva as regras do verificador para o sistema de tipos. eBPF is powerful, but writing eBPF in C means fighting the verifier. Vigil brings the rules of the verifier into the type system.

PySintaxe de PythonPython syntax

Indentação, def, if, for, f-strings e decoradores. Sem cabeçalhos, sem macros, sem ponteiros.

Indentation, def, if, for, f-strings and decorators. No headers, no macros, no pointers.

✓Seguro para o verificadorVerifier-safe

Laços sem limite, recursão, ponto flutuante e acessos não verificados ao pacote são erros de compilação, apontados no seu código.

Unbounded loops, recursion, floating point and unchecked packet accesses are compile errors, pointed out in your code.

Hash, LRU, per-CPU arrays, ring buffers and tail calls, declared at the top of the file and used through typed methods.

RastreamentoTracing

Um programa é uma função com o decorador do seu tipo. Este conta, por processo, os arquivos abertos, num mapa que o espaço de usuário lê.

A program is a function with the decorator of its type. This one counts the files each process opens, in a map that userspace reads.

# Counts the files opened by each process.
from std.bpf import KprobeContext, pid_tgid

map opens: Hash[u32, u64](max_entries=10240)

@kprobe("do_sys_openat2")
def count_opens(ctx: KprobeContext) -> i32:
    pid = u32(pid_tgid() >> 32)
    count = opens.get_or_insert(pid, 0)
    count += 1
    return 0

PacotesPackets

ctx.parse[H](offset) devolve o cabeçalho, ou None se o pacote for curto demais; ? deixa o pacote passar. É exatamente a verificação de limites que o verificador exige.

ctx.parse[H](offset) gives the header, or None if the packet is too short; ? lets the packet pass. That is exactly the bounds check the verifier demands.

from std.net import XdpContext, XdpAction, EthHdr, Ipv4Hdr, ETH_HLEN, ETH_P_IP

map blocked: Hash[u32, bool](max_entries=1024)

@xdp(iface="eth0")
def firewall(ctx: XdpContext) -> XdpAction:
    eth = ctx.parse[EthHdr](0)?
    if eth.proto != ETH_P_IP:
        return XdpAction.PASS
    ip = ctx.parse[Ipv4Hdr](ETH_HLEN)?
    if blocked.contains(ip.saddr):
        return XdpAction.DROP
    return XdpAction.PASS

Erros no lugar certoErrors in the right place

Em vez de uma lista de instruções rejeitadas pelo verificador, você recebe um erro na linha do problema, com uma sugestão.

Instead of a listing of instructions the verifier rejected, you get an error on the line of the problem, with a suggestion.

def halve(n: u32) -> u32:
    # error[E0412]: `while` loops need a bound
    while n > 100:
        n = n // 2
    return n

Comece agoraGet started

O compilador é um único executável, com a biblioteca padrão embutida. Para gerar objetos eBPF pelo LLVM ele usa o clang; o backend certificado e o playground dispensam. The compiler is a single executable, with the standard library built in. It uses clang to make eBPF objects through LLVM; the certified backend and the playground do not.

Instale o compiladorInstall the compiler

curl -fsSL https://vigil-lang.github.io/install.sh | sh

Linux e macOS, em x86_64 e aarch64; instala vigil em ~/.local/bin. Leia o script antes de executá-lo, ou compile do código-fonte: cd compiler && cargo build --release.

Linux and macOS, on x86_64 and aarch64; installs vigil in ~/.local/bin. Read the script before running it, or build from source: cd compiler && cargo build --release.

Verifique e compile um programaCheck and build a program

vigil check examples/xdp_firewall.vg
vigil build examples/xdp_firewall.vg -o firewall.o     # clang ≥ 15
vigil build examples/xdp_firewall.vg --emit ir         # LLVM IR, no clang

    Tutorial de VigilA tour of Vigil

    Este tutorial apresenta a linguagem por exemplos. Todo bloco de código tem um botão Experimentar, que o abre no playground: lá o compilador roda no seu navegador e mostra os erros, o LLVM IR gerado e, para os programas do subconjunto Vigil Core, as instruções eBPF — que você pode executar sobre um pacote.

    Blocos com a borda vermelha são programas que o compilador rejeita, de propósito: abra-os para ver a mensagem de erro.

    This tutorial presents the language by example. Every code block has a Try it button that opens it in the playground: there the compiler runs in your browser and shows the errors, the generated LLVM IR and, for programs of the Vigil Core subset, the eBPF instructions — which you can run on a packet.

    Blocks with a red border are programs the compiler rejects, on purpose: open them to see the error message.

    O que é eBPF, e por que VigilWhat eBPF is, and why Vigil

    eBPF permite carregar pequenos programas no kernel Linux, que rodam quando algo acontece: uma função do kernel é chamada (kprobes), um evento é registrado (tracepoints), um pacote chega à placa de rede (XDP) ou passa pela pilha de rede (TC), uma verificação de segurança é feita (LSM). Os programas guardam estado em mapas, que o espaço de usuário também lê e escreve.

    Antes de aceitar um programa, o kernel o submete ao verificador, que exige garantias: todo laço termina, todo acesso à memória está dentro dos limites, não há ponto flutuante nem recursão, a pilha tem no máximo 512 bytes. Em C, violar essas regras resulta numa rejeição em termos de instruções de máquina. Vigil é uma linguagem com a sintaxe de Python cujo sistema de tipos conhece essas regras: o que o verificador rejeitaria é um erro de compilação, apontado no seu código.

    eBPF loads small programs into the Linux kernel, which run when something happens: a kernel function is called (kprobes), an event is recorded (tracepoints), a packet reaches the network card (XDP) or goes through the network stack (TC), a security check is made (LSM). Programs keep state in maps, which userspace reads and writes too.

    Before it accepts a program, the kernel runs it through the verifier, which demands guarantees: every loop ends, every memory access is within bounds, there is no floating point and no recursion, the stack is at most 512 bytes. In C, breaking these rules ends in a rejection phrased in machine instructions. Vigil is a language with the syntax of Python whose type system knows those rules: what the verifier would reject is a compile error, pointed out in your code.

    Um primeiro programaA first program

    # Prints a line to the trace pipe every time a file is opened.
from std.bpf import KprobeContext, pid_tgid

@kprobe("do_sys_openat2")
def on_open(ctx: KprobeContext) -> i32:
    pid = pid_tgid() >> 32
    print(f"openat2 called by pid {pid}")
    return 0

    Um programa é uma função de nível superior com o decorador do seu tipo (@kprobe), que recebe o contexto desse tipo e devolve um inteiro. Aqui, a cada chamada da função do kernel do_sys_openat2, o programa lê o identificador do processo com o helper pid_tgid() da biblioteca padrão e escreve uma linha com print.

    Na linha de comando, vigil check arquivo.vg verifica o programa e vigil build arquivo.vg gera o objeto eBPF (com o clang), que ferramentas como bpftool ou bibliotecas como libbpf e aya carregam no kernel.

    A program is a top-level function with the decorator of its type (@kprobe), which takes the context of that type and returns an integer. Here, every time the kernel function do_sys_openat2 is called, the program reads the process id with the pid_tgid() helper of the standard library and writes a line with print.

    On the command line, vigil check file.vg checks the program and vigil build file.vg makes the eBPF object (with clang), which tools such as bpftool or libraries such as libbpf and aya load into the kernel.

    Tipos e variáveisTypes and variables

    Os tipos básicos são os inteiros u8 u16 u32 u64 usize (sem sinal) e i8 i16 i32 i64 (com sinal), e bool. Inteiros nunca se convertem implicitamente: u32 + u64 é um erro de tipo. A conversão é uma chamada do tipo, como u64(x), que também aceita um bool (1 ou 0).

    The basic types are the integers u8 u16 u32 u64 usize (unsigned) and i8 i16 i32 i64 (signed), and bool. Integers never convert implicitly: u32 + u64 is a type error. A conversion is a call of the type, such as u64(x), which also accepts a bool (1 or 0).

    def mix(a: u32, b: u64) -> u64:
    small: u8 = 0b1010      # the literal takes the type u8
    wide = u64(a) + b       # explicit conversion
    half = wide // 2        # integer division is //
    flag = u64(a > 3)       # a bool is 1 or 0
    return half + flag + u64(small)

    Uma variável é declarada na primeira atribuição. Seu tipo é inferido de todos os seus usos na função; um literal inteiro assume o tipo que o contexto exige. Anote o tipo (x: u64 = 0) quando nada mais o determina. Os parâmetros e o tipo de retorno são sempre anotados.

    A variable is declared by its first assignment. Its type is inferred from all its uses in the function; an integer literal takes the type its context demands. Annotate the type (x: u64 = 0) when nothing else decides it. Parameters and return types are always annotated.

    def total(xs: u32[4]) -> u32:
    sum = 0             # u32: it is returned below
    for x in xs:
        sum += x
    big: u64 = 1 << 40  # an annotation fixes the type
    return sum + u32(big >> 40)

    As operações seguem as instruções do eBPF: a aritmética dá a volta (wraps), x // 0 == 0 e x % 0 == x. Não há números de ponto flutuante em tempo de execução — o verificador os rejeita. Para frações, use fixed[I, F] de std.fixed (ponto fixo), ou calcule em tempo de compilação (veja Código em tempo de compilação).

    Operations follow the eBPF instructions: arithmetic wraps, x // 0 == 0 and x % 0 == x. There are no floating-point numbers at run time — the verifier rejects them. For fractions, use fixed[I, F] from std.fixed (fixed point), or compute at compile time (see Compile-time code).

    Arrays, constantes e tuplasArrays, constants and tuples

    Um array T[N] tem tamanho conhecido na compilação. [x] * N cria N cópias. Um índice constante é verificado pelo compilador; um índice calculado em tempo de execução que sai dos limites aborta o programa.

    An array T[N] has a length known at compile time. [x] * N makes N copies. A constant index is checked by the compiler; an index computed at run time that is out of bounds aborts the program.

    const PRIMES: u8[4] = [2, 3, 5, 7]
const MASK: u32 = (1 << 24) - 1

type Port = u16

def sum_rows(grid: u32[4][2]) -> u32:
    total: u32 = 0
    for row in grid:          # two rows of four
        for x in row:
            total += x
    zeros = [0] * 8
    zeros[3] = total
    return zeros[3] + grid[1][0] + u32(PRIMES[1])

def ordered(a: u32, b: u32) -> u32:
    lo, hi = a, b             # several assignments at once
    if lo > hi:
        lo, hi = hi, lo
    return (hi - lo) & MASK

    Funções, structs e métodosFunctions, structs and methods

    Funções recebem argumentos por valor. Parâmetros podem ter valores padrão e as chamadas podem nomear argumentos. Todas as funções são incorporadas (inlined) nos programas que as chamam; recursão é proibida, pois a pilha do eBPF é pequena e fixa.

    Functions take their arguments by value. Parameters may have default values and calls may name their arguments. All functions are inlined into the programs that call them; recursion is forbidden, since the eBPF stack is small and fixed.

    struct Point:
    x: i32
    y: i32

    def norm1(self) -> i32:
        return max(self.x, -self.x) + max(self.y, -self.y)

    def origin() -> Point:      # no self: called as Point.origin()
        return Point(0, 0)

struct Counter:
    n: u64

    @mut                        # changes self
    def bump(self, by: u64 = 1):
        self.n += by

def demo(p: Point) -> u64:
    q = Point(y=p.y, x=p.x + 1)
    c = Counter(0)
    c.bump()
    c.bump(by=10)
    if q.norm1() > Point.origin().norm1():
        c.bump()
    return c.n

    Um struct é construído chamando-o com seus campos, por posição ou por nome. Um método que altera self precisa de @mut.

    A struct is built by calling it with its fields, by position or by name. A method that changes self needs @mut.

    Enums e matchEnums and match

    Variantes de um enum podem carregar valores, que match desmonta. O match precisa cobrir todos os casos — esquecer um é erro de compilação.

    The variants of an enum may carry values, which match takes apart. A match must cover every case — forgetting one is a compile error.

    enum Proto:
    Tcp
    Udp
    Other(u8)

    def of(n: u8) -> Proto:
        match n:
            case 6:
                return Proto.Tcp
            case 17:
                return Proto.Udp
            case _:
                return Proto.Other(n)

    def number(self) -> u8:
        match self:
            case Proto.Tcp:
                return 6
            case Proto.Udp:
                return 17
            case Proto.Other(n):
                return n

def classify(n: i32) -> u8:
    match n:
        case 0:
            return 0
        case 1 | 2 | -1:          # alternatives
            return 1
        case x if x > 100:        # a guard
            return 2
        case _:
            return 3

    Option e ?Option and ?

    Option[T], também escrito T?, é Some(valor) ou None. O operador ? extrai o valor, ou sai da função quando é None: numa função que devolve um Option, devolve None; num programa, devolve o padrão do tipo de programa (XDP_PASS para XDP).

    Option[T], also written T?, is Some(value) or None. The ? operator takes the value out, or leaves the function when it is None: in a function that returns an Option, it returns None; in a program, it returns the default of the program type (XDP_PASS for XDP).

    def first_even(xs: u32[4]) -> u32?:
    for x in xs:
        if x % 2 == 0:
            return Some(x)
    return None

def next_even(xs: u32[4]) -> u64?:
    x = first_even(xs)?         # None: next_even returns None
    return Some(u64(x) + 1)

def or_zero(o: Option[u32]) -> u32:
    match o:
        case Some(v):
            return v
        case None:
            return 0

    Consultas a mapas e a leitura de cabeçalhos de pacotes devolvem opções: ? é como a maioria dos programas lê pacotes e mapas.

    Map lookups and reading packet headers return options: ? is how most programs read packets and maps.

    Laços limitadosBounded loops

    O verificador rejeita laços que ele não consegue limitar. Em Vigil:

    • for i in range(n) e for x in array são sempre limitados;
    • while exige @bounded(N), o máximo de iterações;
    • @unroll pede que o laço seja desenrolado.

    The verifier rejects loops it cannot bound. In Vigil:

    • for i in range(n) and for x in array are always bounded;
    • while needs @bounded(N), the most iterations it may run;
    • @unroll asks for the loop to be unrolled.
    def loops(n: u32) -> u32:
    total: u32 = 0
    for i in range(n):
        total += i
    @bounded(16)
    while total > 100:
        total = total // 2
    @unroll
    for j in range(4):
        if j == 2:
            continue
        total += u32(j)
    return total

    Sem o limite, o compilador recusa o laço:

    Without the bound, the compiler refuses the loop:

    # Rejected: E0412 `while` loops need a bound
def halve(n: u32) -> u32:
    while n > 100:
        n = n // 2
    return n

    Em kernels com bpf_loop (Linux 5.17+), laços longos viram callbacks de bpf_loop, que o verificador examina uma única vez. Troque o kernel-alvo no playground e compare o LLVM IR.

    On kernels with bpf_loop (Linux 5.17+), long loops become bpf_loop callbacks, which the verifier examines only once. Change the target kernel in the playground and compare the LLVM IR.

    Pacotes: XDP e TCPackets: XDP and TC

    Programas XDP rodam quando um pacote chega à placa de rede, antes da pilha de rede do kernel; devolvem um veredito: PASS, DROP, TX, REDIRECT ou ABORTED. ctx.parse[H](offset) devolve uma referência ao cabeçalho H naquele deslocamento, ou None se o pacote for curto demais — a verificação de limites que o verificador exige, sem que você precise escrevê-la.

    XDP programs run when a packet reaches the network card, before the kernel's network stack; they return a verdict: PASS, DROP, TX, REDIRECT or ABORTED. ctx.parse[H](offset) gives a reference to the header H at that offset, or None if the packet is too short — the bounds check the verifier demands, without you writing it.

    from std.net import XdpContext, XdpAction, EthHdr, Ipv4Hdr, UdpHdr, ETH_HLEN, ETH_P_IP, IPPROTO_UDP, UDP_HLEN

# The fixed header of DNS. Fields of @network_order structs are big-endian.
@network_order
struct DnsHdr:
    id: u16
    flags: u16
    qdcount: u16
    ancount: u16
    nscount: u16
    arcount: u16

@xdp(iface="eth0")
def dns_guard(ctx: XdpContext) -> XdpAction:
    eth = ctx.parse[EthHdr](0)?          # too short: XDP_PASS
    if eth.proto != ETH_P_IP:
        return XdpAction.PASS
    ip = ctx.parse[Ipv4Hdr](ETH_HLEN)?
    if ip.protocol != IPPROTO_UDP or ctx.len() > 512:
        return XdpAction.PASS
    udp_off = ETH_HLEN + ip.header_len()
    udp = ctx.parse[UdpHdr](udp_off)?
    if udp.dport != 53:
        return XdpAction.PASS
    dns = ctx.parse[DnsHdr](udp_off + UDP_HLEN)?
    if dns.qdcount == 0:
        return XdpAction.DROP
    return XdpAction.PASS

    Atribuir a um campo de um cabeçalho altera o pacote. Este programa TC troca os endereços MAC e decrementa o TTL:

    Assigning to a field of a header changes the packet. This TC program swaps the MAC addresses and decrements the TTL:

    from std.net import TcContext, TcAction, EthHdr, Ipv4Hdr, ETH_HLEN, ETH_P_IP

@tc(direction="ingress", iface="eth0")
def bounce(ctx: TcContext) -> TcAction:
    eth = ctx.parse[EthHdr](0)?
    if eth.proto != ETH_P_IP:
        return TcAction.OK
    ip = ctx.parse[Ipv4Hdr](ETH_HLEN)?
    if ip.ttl > 1:
        ip.ttl = ip.ttl - 1
    mac = eth.src
    eth.src = eth.dst
    eth.dst = mac
    return TcAction.OK

    MapasMaps

    Mapas guardam estado entre execuções e são compartilhados com o espaço de usuário. São declarados no nível superior e usados pelo nome:

    Maps keep state between runs and are shared with userspace. They are declared at the top level and used by name:

    DeclaraçãoDeclarationTipo no kernelKernel type
    Hash[K, V](max_entries=N)BPF_MAP_TYPE_HASH
    LruHash[K, V](max_entries=N)hash que descarta a entrada menos usadaa hash that evicts the least recently used entry
    PerCpuHash[K, V](max_entries=N)um valor por CPUa value per CPU
    Array[V, N], PerCpuArray[V, N]arrays com chavesarrays with keys of type u32
    ProgArray(max_entries=N)programas, para tail callsprograms, for tail calls
    event e: RingBuf[T](size=N)ring buffer de eventosa ring buffer of events
    from std.bpf import KprobeContext, pid_tgid, ktime_ns

struct Stats:
    calls: u64
    last: u64

map counts: Hash[u32, u64](max_entries=1024)
map stats: LruHash[u32, Stats](max_entries=1024)
map per_cpu: PerCpuArray[u64, 4]

@kprobe("do_sys_openat2")
def on_open(ctx: KprobeContext) -> i32:
    pid = u32(pid_tgid() >> 32)
    count = counts.get_or_insert(pid, 0)     # a reference into the map
    count += 1                               # changes the map
    st = stats.get_or_insert(pid, Stats(0, 0))
    st.calls += 1
    st.last = ktime_ns()
    slot = per_cpu[pid % 4]?
    slot += 1
    match stats.get(pid):
        case Some(s):
            print(f"pid {pid}: {s.calls} calls")
        case None:
            pass
    return 0

    get devolve uma referência opcional ao valor no mapa; get_or_insert cria a entrada se preciso. Ler uma referência copia o valor; atribuir através dela altera o mapa.

    get gives an optional reference to the value in the map; get_or_insert creates the entry if needed. Reading a reference copies the value; assigning through it changes the map.

    EventosEvents

    Um ring buffer envia registros ao espaço de usuário. emit copia um valor para ele e devolve False se estiver cheio.

    A ring buffer sends records to userspace. emit copies a value into it and returns False if it is full.

    from std.bpf import KprobeContext, pid_tgid, ktime_ns, comm

struct OpenEvent:
    pid: u32
    timestamp: u64
    comm: bytes[16]

event opens: RingBuf[OpenEvent](size=256 * 1024)

@kprobe("do_sys_openat2")
def on_open(ctx: KprobeContext) -> i32:
    opens.emit(OpenEvent(
        pid=u32(pid_tgid() >> 32),
        timestamp=ktime_ns(),
        comm=comm(),
    ))
    return 0

    Genéricos e protocolosGenerics and protocols

    Structs, enums e funções recebem parâmetros genéricos: tipos (T), tipos limitados por um protocolo (S: Shape) e constantes (N: usize). Cada uso é compilado à parte (monomorfização), e as dimensões são verificadas na compilação.

    Structs, enums and functions take generic parameters: types (T), types bounded by a protocol (S: Shape) and constants (N: usize). Each use is compiled on its own (monomorphization), and shapes are checked at compile time.

    struct Ring[T, N: usize]:
    items: T[N]
    head: usize

    def empty(zero: T) -> Ring[T, N]:
        return Ring[T, N]([zero] * N, 0)

    @mut
    def push(self, x: T):
        self.items[self.head % N] = x
        self.head += 1

def doubled[N: usize](xs: u32[N]) -> u32[N * 2]:
    out: u32[N * 2] = [0] * (N * 2)
    for i in range(N):
        out[i] = xs[i]
        out[i + N] = xs[i]
    return out

protocol Shape:
    def area(self) -> u64: ...

struct Square(Shape):
    side: u32

    def area(self) -> u64:
        return u64(self.side) * u64(self.side)

def total_area[S: Shape, N: usize](shapes: S[N]) -> u64:
    total: u64 = 0
    for s in shapes:
        total += s.area()
    return total

def demo() -> u64:
    r = Ring[u64, 8].empty(0)
    r.push(5)
    d = doubled[3]([1, 2, 3])
    return r.items[0] + u64(d[5]) + total_area[Square, 2]([Square(2), Square(3)])

    Operadores em structs chamam métodos com os nomes de Python (__add__, __lt__…). É assim que fixed[I, F] e os vetores e matrizes de std.ml.tensor ganham sua aritmética:

    Operators on structs call methods named as in Python (__add__, __lt__…). This is how fixed[I, F] and the vectors and matrices of std.ml.tensor get their arithmetic:

    struct Money:
    cents: u64

    def __add__(self, other: Money) -> Money:
        return Money(self.cents + other.cents)

    def __lt__(self, other: Money) -> bool:
        return self.cents < other.cents

def total(xs: Money[3]) -> Money:
    t = Money(0)
    for x in xs:
        t += x
    if t < Money(10):
        return Money(10)
    return t

    Código em tempo de compilaçãoCompile-time code

    Uma comptime def roda dentro do compilador. Ela pode usar f64 e funções matemáticas (exp, log, sqrt, tanh…), e seus laços não precisam de limite. É assim que se calculam tabelas, máscaras e pesos quantizados, que chegam ao kernel como constantes.

    A comptime def runs inside the compiler. It may use f64 and math functions (exp, log, sqrt, tanh…), and its loops need no bound. This is how tables, masks and quantized weights are computed, which reach the kernel as constants.

    from std.fixed import q8_8, quantize

comptime def logistic(x: f64) -> f64:
    return 1.0 / (1.0 + exp(-x))

# The logistic function on [-8, 8), in steps of 1/4, in q8_8.
comptime def sigmoid_table() -> i32[64]:
    table: i32[64] = [0] * 64
    for i in range(64):
        x = (f64(i) - 32.0) / 4.0
        table[i] = i32(quantize(logistic(x), 8))
    return table

const SIGMOID: i32[64] = sigmoid_table()

def sigmoid(x: q8_8) -> q8_8:
    # 4x, rounded down, is the raw value (256x) shifted right by 6
    i = min(max((x.to_raw() >> 6) + 32, 0), 63)
    return q8_8(SIGMOID[i])

    Vigil Core e o backend certificadoVigil Core and the certified backend

    O compilador tem dois geradores de código. O principal gera LLVM IR, que o clang compila para eBPF. O segundo, o backend certificado, compila diretamente para instruções eBPF, sem LLVM, os programas de Vigil Core — o subconjunto formalizado em Lean: programas XDP e TC sobre inteiros, bool e arrays locais, com if, for i in range(N), bytes do pacote em deslocamentos constantes (ctx.parse[Byte](12)?.value), o tamanho do pacote e vereditos. Sem mapas, helpers, structs ou chamadas de função.

    Como esse backend não depende do clang, ele roda no navegador — e o playground executa o código gerado sobre um pacote que você escolhe. Abra este filtro, vá à aba Executar e teste os pacotes DNS e NTP:

    The compiler has two code generators. The main one makes LLVM IR, which clang compiles to eBPF. The second, the certified backend, compiles straight to eBPF instructions, without LLVM, the programs of Vigil Core — the subset formalized in Lean: XDP and TC programs over integers, bool and local arrays, with if, for i in range(N), bytes of the packet at constant offsets (ctx.parse[Byte](12)?.value), the length of the packet and verdicts. No maps, helpers, structs or function calls.

    Since that backend does not need clang, it runs in the browser — and the playground runs the generated code on a packet you choose. Open this filter, go to the Run tab and try the DNS and NTP packets:

    # Drops IPv4 UDP datagrams to port 53, reading the bytes of the packet at
# constant offsets: a program of Vigil Core.
from std.net import XdpContext, XdpAction, Byte

@xdp
def dns_drop(ctx: XdpContext) -> XdpAction:
    # EtherType 0x0800 (IPv4).
    if ctx.parse[Byte](12)?.value != 8 or ctx.parse[Byte](13)?.value != 0:
        return XdpAction.PASS
    # No IP options, and UDP.
    if ctx.parse[Byte](14)?.value != 0x45 or ctx.parse[Byte](23)?.value != 17:
        return XdpAction.PASS
    port = u16(ctx.parse[Byte](36)?.value) << 8 | u16(ctx.parse[Byte](37)?.value)
    if port == 53:
        return XdpAction.DROP
    return XdpAction.PASS
